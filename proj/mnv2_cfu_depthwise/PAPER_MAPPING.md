# Paper-to-implementation mapping

Source: *RISC-V Based TinyML Accelerator for Depthwise Separable Convolutions in Edge AI* (Yildirim and Ozturk).

This file distinguishes implemented behavior from claims that cannot be reconstructed exactly from the paper alone.

| Paper characteristic | Implementation | Verification / note |
|---|---|---|
| Tightly coupled RISC-V CFU | `gateware/fused_depthwise.py`, generated by `cfu_gen.py` as top module `Cfu` | Uses the repository's `amaranth_cfu.simple_cfu` handshake and custom R-type instruction path. |
| Full Expansion -> Depthwise -> Projection fusion | Gateware FSM and `Mnv2FusedReference` compute all three stages before exposing output | `gateware/test_fused_depthwise.py` compares a complete fused pixel with an independent model. |
| Pixel-wise dataflow | One 3x3 input patch produces one complete projected output pixel | No expansion or depthwise feature map is visible to software. |
| Zero intermediate feature-map buffer | Only a 3x3 expanded tile and one depthwise channel vector exist in local registers | Static source scan and tests; no F1/F2 tensor pointers or stores exist. |
| No DMA | Input, weights, parameters and results cross only the CFU instruction operands | There is no bus-master, address, AXI, Wishbone or DMA port in the design. |
| Dedicated expansion, depthwise and projection phases | Separate `EXP_*`, `DW_*`, and `PROJ_*` states | State transitions are exercised by the end-to-end gateware test. |
| INT8 operands and outputs, INT32 accumulation/bias | Signed 8-bit memories/results and signed 32-bit accumulators | Negative-value and saturation cases are covered. |
| 3x3 depthwise kernel / nine taps | Fixed `KERNEL_TAPS = 9` and a nine-tap stream | Tests use all nine taps. |
| On-the-fly padding | `tests/fused_image_model.py` synthesizes the configured input zero-point for invalid coordinates while producing each pixel | Covered for SAME/VALID, stride 1/2, and non-aligned dimensions. The current RTL accepts an already formed patch; moving the address generator into RTL requires a layer-sized IFMAP BRAM configuration not specified by the paper. |
| Input-stationary expansion | The input patch remains in local CFU registers while expansion filters are traversed | Implemented functionally; the compact reference RTL time-multiplexes MAC hardware. |
| NLR depthwise | Each expanded 3x3 channel tile is consumed once to create one depthwise result | Implemented. |
| Output-stationary projection | Projection accumulation stays local until all expanded channels are consumed | Implemented. |
| Requantization / activation | Configurable arithmetic shifts followed by signed INT8 saturation at each stage | This is deterministic fixed-point post-processing, but not the paper authors' unpublished per-layer multiplier tables. |
| Five-stage v3 pipeline | The code preserves five logical phases: expansion MAC, expansion post-process, depthwise MAC, depthwise post-process, projection MAC | The compact portable RTL is scheduled as an FSM, not the paper's exact 178-DSP physical pipeline. |
| Nine expansion engines, 8-way MAC, 9-way depthwise MAC, 56 projection engines | Represented by equivalent logical dataflow and configurable channel loops | Exact parallel replication is intentionally not claimed. The paper gives diagrams/resource totals but no RTL, timing schedule, memory widths, or instruction ABI sufficient for bit-for-bit reconstruction. |
| Nine-bank IFMAP BRAM, nine-bank depthwise weights, LUTRAM projection weights | Logical layouts match `[tap][channel]`, `[tap][expanded]`, `[output][expanded]` | The reference core uses synthesizable register arrays so it runs on all repository targets. Board-specific BRAM/LUTRAM inference directives are not added without the original target constraints. |
| MobileNetV2 TFLM full-model transparent fusion | Not enabled in this reference project | Standard TFLM invokes Expansion, Depthwise and Projection as three independent operators and materializes their tensors. Transparent fusion requires interpreter/delegate changes plus exact block metadata. The paper does not publish that integration code or command protocol. |

## Why several physical details are not claimed as exact

The paper specifies the architectural idea and reports resources, but it does not publish source RTL, CFU opcodes, complete memory dimensions, bank-address formula text (the PDF extraction omits the formula), per-layer quantization tables, clock-enable schedule, or TFLM graph-fusion implementation. Reproducing the reported 20,922 LUT / 17,752 FF / 97 BRAM / 178 DSP design exactly is therefore not possible from the paper alone. This project provides a repository-compatible, synthesizable and testable functional implementation of the zero-intermediate-buffer dataflow, with these physical replication gaps made explicit rather than silently invented.
